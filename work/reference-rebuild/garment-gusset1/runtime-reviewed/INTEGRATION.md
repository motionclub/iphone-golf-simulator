# Reviewed runtime integration

Copy only `HeroGarmentGusset.cs`, `HeroGarmentGussetLifetime.cs`, and the changed `HeroGarmentLOD.cs` into production scripts, together with the **reviewed** full/LOD JSON profiles from this folder. These include exact generated-face-to-source-face mapping for preserving every runtime submesh/material slot. Do not copy `compile-stubs.cs` or compilation outputs. Keep the source author's final-pose `HeroGarmentGusset.Apply(look.female, look.transform, top)` hook after TailoredSleeve weights.

The runtime now caches full and LOD states separately per renderer. `CanonicalSource` resolves a deforming mesh back to its immutable source; LOD uses this when saving full and match references. LOD crossings select the existing state instead of destroying and rebuilding it. A lifetime component restores any surviving renderer's canonical source and destroys/removes every owned mesh/state when its hero is destroyed. The original candidate remains unchanged outside this folder.

Each state compares all current bone-to-hero matrices element by element and all active mesh shape weights using exact float equality. Unchanged poses reuse the existing corrected buffer and skip collision plus mesh upload, including after reactivating a cached LOD. No epsilon or previous-frame deformation enters the solver. Failed evaluation does not mark a pose reusable. Every original solver/contact/normal expression remains unchanged.

Telemetry is disabled unless `VISUAL_UNDERARM_GUSSET_STATS=1` at Unity process startup. Call public `HeroGarmentGussetLifetime.BeginCaptureStats()` before a complete capture; call `GetCaptureStats()` to save `JsonUtility.ToJson(...)` at any point before destruction; call `EndCaptureStats()` once to emit one aggregate log. Allocation numbers use `GC.GetAllocatedBytesForCurrentThread`; build totals include profile loading and State construction, while apply totals measure matrix/shape comparison, solver and native mesh setters. Renderer dictionary/lifetime component creation occurs outside the build allocation bracket. Timing covers main-thread calls and native upload submission, not GPU time. Telemetry itself allocates only when obtaining/reporting the aggregate object, outside the measured Apply block.

`code-scope-costs.json` records structural costs, not measured milliseconds or a phone performance claim. Changed full poses issue 51,416 rays; changed match poses issue 51,231 rays. Match detail barely reduces solver collision cost. Exact unchanged poses skip all rays and mesh upload. The zero-managed-Apply-allocation target must be checked with the telemetry in actual Unity; no Unity execution was performed here.

Compilation: installed Unity 6000.3.24f1 reference assemblies + bundled Roslyn pass for helper/lifetime and for all three files with small production dependency stubs (`compile-all.rsp`). This checks API/compiler compatibility only; root must verify actual mesh/bone/shape parity, full-to-match-to-full, two female renderer independence, destruction, and timing in serialized Unity capture.

Review limits: position correction uses heroRoot-inverse * current bone world * source bindpose, and proxy bind points use current bone world directly; this correctly composes the renderer-to-root axis conversion recorded by the existing snapshot oracle. Production shapes are single frame 100 and transfer keeps all frame position/normal/tangent deltas. GPU lighting normals remain the source candidate's geometric-difference heuristic; it does not prove that imported shaped normals equal geometric normals, and runtime pixel comparison remains required. Existing production corrective index caching still allocates on a mesh change, outside this helper's per-pose solver allocation bracket.

## One-run actual runtime gate

`HeroGarmentGussetRuntimeGate.cs` is an optional Editor-only harness for root to stage under Assets/Editor. At the end of the existing capture coroutine, call `yield return HeroGarmentGussetRuntimeGate.RunGate(game, output);` before Finish/Exit. Or use executeMethod `GolfArcade.EditorTools.HeroGarmentGussetRuntimeGate.RunStandalone` in a separate serialized Unity launch. Both require gusset+stats environment flags at process startup. The repository production factory is `TennisHeroSetup.Attach`, not a HeroFactory class. The harness builds two temporary female TennisActors through actual production APIs; samples final poses through Driver.Sample; checks unchanged solver skips/zero measured managed Apply bytes, full/match/full/match mesh reuse, per-submesh triangle preservation, independent renderer buffers, and cache/native-mesh cleanup after deferred destruction. It restores previous global detail flags/component enable states, writes `gusset-runtime-gate.json`, and throws on failure. No Unity execution was performed while authoring it.
