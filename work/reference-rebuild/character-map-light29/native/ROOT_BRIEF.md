# Optional native character presentation fill

Narrow patch: native-character-presentation-fill.patch against the current GolfArcade/Unity/MatchHeroSurfaces.swift. Production is untouched. VISUAL_CHARACTER_STAGE_LIGHT=1 selects 0.65 warm linear fill (1,.95,.88) when a hero material is created; otherwise existing shader strings/material creation remain exact. The patch only selects TennisCharacter/TennisCloth looks. Existing sun, ambient, camera, environment, course, court, ball and physical-light counts are untouched.

Native SceneKit surface geometric fields are view space (local SDK SCNShadable.h). The fill converts world up via scn_frame.viewTransform, then computes the same Unity view/up/right direction: normalize(view*.8 + up*.6 - right*.3). A guarded normalization handles vertical camera views. Skin/eye fill uses the shared Unity broad skin or character response. Cloth fill reuses the current native cloth/garment response, including fabric-version2; its material maps and altered normals are evaluated first.

The computed fill is added to the existing surface emission once per fragment, after existing surface code. It is not put in the per-light modifier, so adding/removing physical lights cannot multiply it. Existing emission/rim is retained, and cloth shoulder handling remains downstream. An idempotence check prevents a second append on the same material.

No GPU, SceneKit render, Unity or phone run. Standalone shader syntax cannot establish successful generated SceneKit pipeline compilation or visual parity: root must render native with the flag once to accept it. SceneKit-native energy/exposure already differs from URP; this patch matches fill geometry/color and the current native response, without promising pixel parity.

Pigment finding corrected after root’s shader audit: native and active Unity TennisCharacter.shader both use male(.99,.83,.80), female(.99,.76,.74), dark(.80,.67,.64). The stronger HeroOriginalSeamAnatomy LUT is overridden by the shader’s skin-pigment branch. Therefore the earlier active native-vs-Unity pigment mismatch inference was incorrect; no native hue work is included. Root reported actual native12 renders compiled with zero errors/magenta, but the optional fill is overly bright in the existing studio and default remains0 pending native on-map acceptance. This report is root’s actual result, not a GPU run by this agent.
