# Connected shoulder-band integration contract

Read-only source review; no production/Assets changes, Unity execution, GPU use, or new geometry approach. Candidate remains unproven. Astra's current Full prototype is 17708 vertices / 24510 triangles, including 2688 interior panel vertices; these are provisional counts, not acceptance targets. Its actual cuts are arm mass .15/.90 rather than the earlier .2/.8 sketch.

## Native compatibility

The existing format can represent a connected static replacement Top with fixed rest vertices/normals, UV0, material submeshes, four bone influences, inverse binds and named bind-space corrective targets. MatchHeroData builds SceneKit geometry from the serialized bind mesh; it converts exported absolute morph targets to additive deltas and applies them before skinning. Native has no equivalent of HeroGarmentGusset's per-pose CPU geometry rewrite. A permanent source replacement needs no new native algorithm or shader if it satisfies this existing contract.

Do not carry over the old gusset's free-vertex root binding: that transports CPU-generated posed geometry and cannot independently animate the static export. Diagnostic interpolation between already posed boundary loops is useful evidence, but is not an exportable animated source unless the resulting rest mesh, fixed bindings and corrective channels reproduce it under the original rig.

### Specific integration constraints

1. Install the persistent replacement before MatchHeroLockerExport.Collect. ExportSex calls OwnMaterials, prepares the Distance kit separately through HeroGarmentHemWeights.Prepare, and then captures each PartSource.mesh pointer once. HeroGarmentLOD likewise prepares its own match mesh through HemWeights before selecting mesh and bone palette together. A late mesh replacement in pose Apply can leave the exporter holding the old pointer. Full and LOD therefore require explicit, independently validated preparation, cache identity and bone palettes.
2. Identify the author's input basis: current preparation is SleeveGeometry -> AxillaWeights -> sport tailoring/normals -> PoseCorrectives.Prepare. Do not run fitted source geometry through the same displacement/weight fields twice. Root should compare the installed static candidate against the authored basis after preparation, not just its imported FBX.
3. SleeveFit is indexed against its existing source. PoseCorrectives.Prepare accepts a changed count via a generic nearest aligned-surface transfer, allows misses, and assigns zero corrective delta to misses. That is not a safe implicit mapping for a new shoulder band. Supply explicit old-source correspondence plus candidate-specific position/normal deltas, or a verified candidate profile for each detail. Preserve retained channels outside the replacement; explicitly attenuate/generated channels inside it with matching endpoint behavior. Verify normals against the candidate's own rest basis. LocalFit is disabled in this lane.
4. Correctives must remain fixed bind-space shapes, applied once. ExportRig serializes only the last frame of each Unity blend shape and scales live controls by that frame's weight. A single frame at100 with unique existing TailoredSleeve names meets this contract. Do not combine CPU posed displacements with the same nonzero GPU/native morph deltas.
5. ExportRig uses mesh.boneWeights (four Float32 weights / four UInt8 local indices), requires one row per vertex and one bind matrix per renderer bone. It normalizes weights and silently repairs zero rows to bone0 with a warning. Candidate validation must instead reject zero/nonfinite rows, out-of-range indices, truncation surprises and inconsistent actual seam bindings. Preserve original53 character bones and bone/rest identity; no shoulder helper bones.
6. Kit UV0 is mandatory and has exactly one Vector2 per vertex. Normals must match vertex count. Preserve semantic Kit_Top material submesh assignments, original texture names and intended winding. Retained UV seams may keep distinct UVs/normals, but true positional seam aliases need identical dense bindings and consistent positional morph offsets. New-band UVs must be explicit; nearest geometric correspondence alone does not preserve the fabric map.
7. VISUAL_UNDERARM_GUSSET must be0 for the connected source proof. Its old Full13932/LOD11533 source checks and18401/15989 output ownership gate describe the rejected dynamic helper. Do not relax those counts to load its stale profile onto the new source. Keep DQ/contact/LocalFit off for this lane.

Exporter caveat: its self-check re-reads the current live mesh.vertices rather than decoding its earlier serialized bind-position block. A dynamically rewritten mesh can therefore pass that local check while native receives a frozen earlier pose. The static-basis invariance gate plus an independent serialized-data reconstruction closes this gap.

## Export/resource footprint

Use new work directories for candidate export/goldens; do not overwrite the paused accepted-face adoption proof. Existing entry points are GolfArcade.EditorTools.MatchHeroLockerExport.Run and RunDistance with MH_LOCKER_OUT / MH_LOCKER_GOLDEN / MH_LOCKER_REPORT. Keep original accepted face flags. If filenames and Kit_Top material/texture names are retained, native topology changes replace the existing manifest/base/Rig/Swing LZFSE contents; no Xcode resource registration changes are needed. Unity source mesh/profile assets need their normal resource/import integration, but native does not consume SleeveFit JSON directly: it needs the resulting mesh morph targets plus baked per-clip morph-control tracks. Any new texture names would require packaging and exact PBX resource registration in both app targets; no new maps are currently proposed.

Record final exact Full/LOD counts, source/shape/UV/weight hashes, expanded rig bytes and unchanged resource-name set before adoption.
